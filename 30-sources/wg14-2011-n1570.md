# WG14 N1570: ISO/IEC 9899:201x Committee Draft

## Reference

ISO/IEC JTC 1/SC 22/WG 14. *ISO/IEC 9899:201x, Programming Languages — C*.
Committee Draft N1570, 12 April 2011.
[Official WG14 PDF](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf).

## Research question

How does a mature systems-language specification distinguish requirements,
documented implementation choices, unspecified values, traps, translation
limits, and undefined behavior?

## Method

The analysis uses N1570 clauses 3 and 4 for terminology and conformance,
clause 5 for environmental limits, and the informational portability annexes.
N1570 is a committee draft closely preceding C11, not a Catena authority.

## Findings

- An implementation-defined value is an unspecified value for which each
  implementation documents how the choice is made.
- An unspecified value is valid but the standard does not require one choice
  in a particular instance.
- A trap interrupts execution so that the program performs no further
  operations.
- C distinguishes constraints that require diagnostics from other
  requirements and allows conforming implementations and extensions within
  stated boundaries.
- Translation limits supply portable minima, while implementations can support
  more.
- Violating certain requirements, explicit “undefined behavior,” and omission
  of any behavior definition are all routes to undefined behavior in C.

## Relevance

Catena borrows the value of distinct behavior and limit classes but rejects
the undefined-behavior escape hatch. Catena also tightens unspecified behavior
to bounded presentation/internal strategy, makes invalidity transactional,
and requires a distinct diagnostic when a valid input exceeds an
implementation limit.

## Limits

C's object model, optimizer contract, hosted/freestanding distinction,
extensions, and observable behaviors differ substantially from Catena's typed
BEAM target. N1570's classification cannot be imported without narrowing it
for safety, governance, and artifact identity.
