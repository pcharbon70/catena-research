# Catena Design Decision Register

## Purpose

This register is the durable record of every developer fork decision made
during gap-plan review: where a plan posed enumerated options, which
option the developer chose, which option carried the recommendation, and
where the choice became normative. The plan conversations themselves are
the only other place the options-as-posed survive; this register removes
that single point of loss.
The [language completion plan](language-completion-plan.md) adds a second,
explicitly labeled selection provenance: the user delegated the agent to
explore four or more answers and select its recommendation. Those rows record
**agent-selected recommendations under user delegation**, not individual
developer approval. The original user-reviewed choices below keep their
historical meaning.
It records **plan-fork decisions only**. Two neighbors hold related
material and are not duplicated here: decisions that *emerged during
implementation* (for example C022's qualified-references-don't-count
rule, C024's inhabitation seeding) live in each slice's journal under
`## Observations`, and the reasoning for and against each option lives in
each synthesis under "Selected model" and "Rejected alternatives".

**Maintenance rule:** every future gap plan's forks get their rows added
here in the same change as that plan's Phase 1 research bundle.

**Notation:** in each Options column, `(rec)` marks the option the plan
recommended; `†` on the Chosen column marks a developer override of that
recommendation. Two overrides exist so far — the `.cat` extension (C020)
and admitting module recursion (C024) — and both proved durable.

## Language completion plan (2026-09-06)

The user requested the [complete implementation plan](language-completion-plan.md)
and authorized the agent to select the answer it would recommend after
considering at least four alternatives per decision. The plan covers every
immutable checklist item 001–141. It preserves completed contracts, explicitly
holds public vocabulary and the final grammar, and begins implementation only
after the full planning gate.

**Selection provenance for every row in this section:** agent-selected under
the user's explicit delegation. The selected column identifies the recommended
option. The developer delegated the selection process rather than selecting
each row separately; no per-fork developer override is recorded in this plan.
Selected directions remain non-normative until their item-specific admission
and evidence gates pass. Each volume's item section links the research,
normative contract, implementation targets, dependencies and acceptance tests.

The four-option rows from the hub and three volumes are preserved below in
their original wording. Implementation discoveries and any later change of
recommendation belong in the
[execution journal](../50-journal/2026-09-06-language-completion-plan.md),
with their own alternatives and reasons. This initial record stays intact.
