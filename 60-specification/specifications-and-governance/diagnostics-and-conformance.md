# Specification and Governance Diagnostics and Conformance

## Stable diagnostic families

Version 0.1.6 reserves:

| Identifier | Meaning |
| --- | --- |
| `SPC001` | unknown, private, or kind-mismatched claim subject |
| `SPC002` | malformed, duplicate, or unstable claim identity |
| `SPC003` | rule checker is missing, mistyped, effectful, or not verification-only |
| `SPC004` | example is malformed or incompatible with the checker |
| `EVD001` | evidence is malformed, stale, revoked, duplicated, or wrongly bound |
| `EVD002` | example or checker returned counterexample or runtime error |
| `EVD003` | deterministic checking budget exhausted |
| `GOV001` | no applicable policy, missing requirement, or explicit denial |
| `GOV002` | malformed or over-budget policy |
| `GOV003` | invalid, duplicate, unauthorized, or revoked signature or actor |
| `GOV004` | invalid lifecycle edge, sequence, prior digest, or terminal transition |
| `GOV005` | invalid delegation, root rotation, revocation, or recovery chain |
| `ART001` | unsafe, colliding, substituted, or mismatched artifact path or digest |
| `ERS001` | verification material escaped erasure or is referenced at runtime |

Diagnostics MUST name the requested action, governed subject, applicable
policy, failing requirement, expected and observed digest or state when
relevant, and source or bundle path. A policy failure includes the ordered
decision tree; threshold nodes report required, valid, invalid, revoked, and
duplicate counts separately.

## Required corpus

The immutable conformance revision MUST pass:

- all 0.1.1 through 0.1.5 tests unchanged;
- an ungoverned 0.1.6 compatibility package;
- optional adoption and build-versus-publish scope cases;
- subject resolution for every supported kind and rejection of future kinds;
- typed, mistyped, effectful, and runtime-referenced rule checkers;
- supported, counterexample, runtime-error, and budget-exhausted examples;
- formatting-invariant and meaning-sensitive semantic digest cases;
- additive package/module/action/profile policies and explicit deny;
- duplicate-actor, threshold, assumption-authorization, and policy-budget cases;
- valid and invalid Ed25519 signatures, domain substitution, duplicate JSON
  names, unsafe integers, floats, invalid Unicode, and noncanonical payloads;
- evidence and artifact substitution, revocation, replay, and logical-window
  attacks;
- every valid lifecycle edge and every invalid, backward, terminal, skipped,
  reordered, or broken-chain edge;
- normal dual-threshold root rotation and predeclared recovery;
- output traversal, symlink escape, collision, and failed-gate no-output cases;
- sidecar removal without runtime change and exact artifact verification; and
- byte-identical BEAM output with and without fully discharged specifications.

## Independent oracle

A separately structured reference evaluator MUST consume the canonical
governance bundle, trust root, evidence results, and candidate artifact set and
produce the same decision, lifecycle state, and explanation as the production
evaluator. It MUST NOT call the production policy evaluator.

Fixtures generated by the compiler are insufficient as their own oracle.
Canonicalization uses published RFC 8785 examples, and Ed25519 verification
uses RFC 8032 vectors in addition to local round trips.

## Promotion gate

The C006 semantic boundary became normative only after one immutable compiler
commit had:

1. passed `mix test` and `mix format --check-formatted`;
2. passed the independent oracle and all adversarial corpus cases;
3. demonstrated OTP 29 Abstract Format as the sole BEAM generation call;
4. demonstrated byte-identical runtime artifacts and a zero-retention erasure
   audit;
5. left no final output after every failed governed action; and
6. been recorded with exact environment, commands, results, and artifact
   digests in a dated journal entry.

The authorized compiler commit
`2f6805e166a086f7d67c2cc0f3023e9e34fe2cec` satisfied this semantic gate on
2026-08-03 under the retired `0.1` through `0.6` protocol identifiers. The
exact environment, commands, results, and artifact digests are recorded in the
[C006 conformance journal](../../50-journal/2026-08-03-c006-executable-specification-governance-conformance.md).
Consequently, P006, P110 through P114, and G115 became C006 and C110 through
C115. P109 remains partial because public source punctuation is outside 0.1.6,
and G116 remains open because long-term schema and compiler evolution are
deliberately excluded.

That historical identity does not establish the exact `0.1.1` through
`0.1.6` protocol strings, regenerated canonical artifacts, or signatures. The
[prototype-slice renumbering record](../../50-journal/2026-08-04-prototype-slice-renumbering.md)
requires fresh cross-slice evidence before a renumbered immutable compiler
identity is published.
