# Clause Condition BEAM Lowering

## Backend boundary

The bootstrap lowers verified typed core to Erlang/OTP 29 Abstract Format and
delegates binary generation to `compile:noenv_forms/2`. It does not emit Core
Erlang, BEAM assembly, or `.beam` bytes directly.

Only typed guard trees with rechecked condition evidence may reach this stage.
Backend optimization cannot repair an unsafe or unproved source condition.

## Native lowering

The portable native mapping is:

| Catena core | Erlang Abstract Format operation |
| --- | --- |
| `not` | `not` |
| lazy `and` | `andalso` |
| lazy `or` | `orelse` |
| exact `==` | `=:=` |
| exact `!=` | `=/=` |
| `<`, `<=`, `>`, `>=` | `<`, `=<`, `>`, `>=` |
| unary `-` | unary `-` |
| `+`, `-`, `*` | corresponding arithmetic operator |

Boolean and integer literals and already bound variables lower directly.
Verified predicate calls are transitively inlined before native lowering, so
no arbitrary local or remote call appears in an Erlang guard sequence.

## Ordinary lowering

For an ordinary match or function, the same expanded condition core may be
evaluated as ordinary pure code followed by a two-way Boolean case. `false`
invokes the prebuilt fallback continuation; `true` evaluates the selected body.
This path exists as a semantics-preserving implementation strategy and a
differential oracle, not as permission to widen source conditions.

Implementations MUST expose or test three lowering selections:

- `auto` — use native lowering when the verified evidence permits it;
- `native` — force the native path for eligible 0.3 conditions; and
- `ordinary` — force pure expression plus conditional branching.

The selected mode may change generated bytes and performance, but not a typed
Catena observation or source diagnostic.

## Shared clause continuation

Each source clause lowers through one continuation receiving its pattern
bindings. Structural alternatives call that continuation after one succeeds.
The continuation performs the condition and either commits to the body or
uses the next source-clause continuation.

This shape ensures:

- the scrutinee is stored once;
- an or-pattern's shared condition is not duplicated;
- a false condition does not retry another alternative of the same source
  pattern;
- the fallback does not retain row-local bindings; and
- a body failure cannot invoke fallback.

Another lowering is conforming when it preserves the same properties.

## Selective receive

The receive harness emits native Erlang receive-clause guards only. It MUST
reject a condition without portable expanded core, a nonclosed message type,
or an or-pattern requiring expansion. No ordinary-branch fallback may consume
and reinsert rejected messages.

## Evidence erasure

Normalized formulas, dependency graphs, fact classifications, solver work
records, and typed guard-tree verification markers may be absent from the
resulting `.beam` after the compiler has checked them. Runtime conditions and
their selected native or ordinary operations remain executable unless an
ordinary semantics-preserving optimization proves them constant.

The version 0.3 `.cati.json` sidecar retains exported condition core and
digests needed for separate compilation. Erasing compiler evidence from BEAM
does not erase that interface contract.
