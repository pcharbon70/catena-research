# C020 Files and Modules

## Observations

Checklist item G020 is complete as C020 and normative source-only language
revision `0.1.16`. The completed boundary fixes the `.cat` extension, the
at-most-one module rule with valid no-module files, ASCII
uppercase-initial module-name spelling aligned with both semantic
frontends, declared-name basename verification, and one exact first-line
generated marker riding on C016 comment forms.

The abstract-events discipline paid off again: because the resolver
consumes parser-supplied module-declaration events rather than parsing
headers, the entire file contract became executable before P109's
declaration grammar exists, exactly as C015 consumed abstract token
capabilities before C019. One boundary decision emerged during testing:
the exact marker requires one space after `//` (`^ catena:generated`),
while the *attempt* pattern is lenient about leading whitespace, so
`//catena:generated by x` and `//  catena:generated by x` are `FIL005`
wrong-spacing failures rather than silently inert comments — recognition
stays byte-exact while near-misses fail loudly.

A pre-existing compiler documentation defect was repaired in the same
change: the CONFORMANCE header rows had stopped at `0.1.14` when C019's
header edit script failed mid-run; they now read through `0.1.16`.

The sibling compiler implementation is commit
[`677a8f4a91f047d3ee97f197992b24401cff9a41`](https://github.com/pcharbon70/catena/commit/677a8f4a91f047d3ee97f197992b24401cff9a41)
on branch `agent/c020-files-and-modules`, prepared from the `rewrite`
integration line for coordinated publication.

## Version and boundary decision

C020 consumes `0.1.16` because it changes source acceptance and file-level
diagnostics. The source decoder now accepts cumulative source revisions
through 0.1.16. Every predecessor API retains its exact selection; no new
implementation limit is introduced, and aggregate file-size limits remain
with the G129 owner.

The retained JSON AST remains closed at 0.1.7, the exact kernel remains
0.1.8, and interface, artifact, signed-format, and compiler-package
versions do not change. The next unused semantic patch is `0.1.17`.
