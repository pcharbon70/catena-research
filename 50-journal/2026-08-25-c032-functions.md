# C032 Functions and Calls

## Observations

Checklist item G032 is complete as C032 and normative source-only
language revision `0.1.28`. The completed boundary fixes the function
model: every function is semantically unary (multi-parameter
definitions desugar to nested unary functions; multi-argument calls
are repeated unary application under C030's order) with no arity
mismatch to diagnose; any prefix application is a first-class closure
value (free partial application); capture is lexical and immutable
with allocation identity G037's exclusion; the let-bound closure is
the local-function form under all of C031's rules; named functions are
definitions with C022's export rules; and the kernel's
proper-tail-call guarantee is elevated verbatim. Zero new diagnostic
families and no new public API.

Three implementation decisions worth recording. First, the deep tail
witness runs on the **kernel S-expression path compiled to BEAM**
(`check_kernel` + `compile_kernel`), not the JSON path — the JSON
AST's sequential environment rejects self-reference, so a named
tail-recursive definition only exists on the kernel boundary; the
witness is therefore doubly honest, exercising the guarantee's
strongest clause (a call after match selection) on the input form
whose calculus states it. The depth is five million iterations: any
per-call stack retention exhausts the machine far before the count,
while a properly tail-optimized run completes in constant stack. The
stepper witnesses the same program at 500 iterations terminating
within its budget. Second, the **witness vocabulary is the C030/C031
template**: 0.1.7 manifests with explicit selection, helpers defined
before `main`, exports restricted to intended names, and the handler's
input/output threaded to the result type — the one recurring trap
being that a handler around a tuple-returning computation needs the
tuple type, not integer. Third, the **named-function interface witness
reads the encoded interface map** (`metadata.interface["values"]`,
string keys) — the decoded struct form is the linker's, not the
compile metadata's.

The sibling compiler implementation is commit
[`0af785cf32de1893c9638ebd145944bdc37f52b3`](https://github.com/pcharbon70/catena/commit/0af785cf32de1893c9638ebd145944bdc37f52b3)
on branch `agent/c032-functions`, pending compiler PR and research
promotion following the established publication order (the PR links
are backfilled at publication).

`functions_and_calls`, static-meaning lifecycle change with migration
note) and adds the `guides/language/functions.md` guide; the evidence
is `c032_functions_test.exs` — no production module, per the
definitional stance.

The focused corpus covers exact selection, lifecycle registration, and
pinned predecessor defaults; curried application through a
two-parameter helper with effectful arguments agreeing on evaluator
and BEAM; partial application as a callable value used twice with its
captured base (15, 17) — the capture-immutability witness; a
let-bound closure passed to a higher-order helper and invoked — the
local-function witness; named exports present in the encoded
interface; the five-million-iteration match-dispatched tail recursion
completing on compiled BEAM with the correct value; stepper
termination of the same program at 500 iterations; determinism; and
the absence of arity, capture-list, local-recursion, and
calling-convention entry points.

## Version and boundary decision

C032 consumes `0.1.28` for the arity model, the desugaring semantics,
partial application, capture discipline, the local-function form, and
the elevated tail guarantee; it adds no JSON AST version, kernel
S-expression version, interface version, artifact version, signature
domain, typing rule, runtime behavior, BEAM representation, manifest
field, public API name, or diagnostic family, and amends no retained
revision. Every predecessor API retains its exact selection. The next
unused semantic patch is `0.1.29`.
