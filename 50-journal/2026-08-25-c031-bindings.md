# C031 Bindings and Sequencing

## Observations

Checklist item G031 is complete as C031 and normative source-only
language revision `0.1.27`. The completed boundary fixes: local `let`
is strictly non-recursive (a self-referential RHS is `T001` unbound)
with plain value-name binders and substitute-after-value timing; scope
is sequential-lexical with silent innermost-wins shadowing of any
in-scope name (C021 restated at the binding level); recursion is
definitions-only — the kernel's signed environment with C024's SCC as
mutual recursion's home; an unused binding stays valid with its RHS
effects preserved; the deny-able `BS001` warning fires exactly on
non-`_`-prefixed binders never occurring in their body; and
`let _ = e1; e2` is the normative sequencing form.

Four implementation decisions worth recording. First, `BS001` keys on
the **compiler build, not the input's revision**: the retained JSON
AST compiles at its own 0.1.1–0.1.8 revisions, so a warning gated on
`language_revision == "0.1.27"` could never fire for any compilable
input. New warnings issuing between revisions is exactly C008's
diagnostics classification (and OTP's model); the deny list is the
control. Second, the JSON AST's **value-name spelling cannot begin
with an underscore** (lowercase-initial rule), so the `_`-prefix
exemption — normative for the surface era — is exercised on typed-core
terms directly; the AST's spelling of the sequencing idiom uses an
ordinary unused name until P109 lands dedicated punctuation. Third,
the **JSON inference environment is sequential**: a definition can
reference only earlier definitions, and self-reference is `T001` —
which makes the retained AST itself a witness for non-recursion, while
the recursion-home witness runs on the kernel S-expression path where
the signed definition environment is normative (a recursive `count`
stepping to termination). Fourth, `BS001` joins the deny-able warning
registry (`@warning_ids`), making the manifest deny list its promotion
mechanism with zero new machinery.

[`17b5be7b1bce9cd6a4603b9d6b6f5f5d8060951b`](https://github.com/pcharbon70/catena/commit/17b5be7b1bce9cd6a4603b9d6b6f5f5d8060951b),
merged into the `rewrite` integration line by compiler PR
[#107](https://github.com/pcharbon70/catena/pull/107) at merge commit
[`75447c1`](https://github.com/pcharbon70/catena/commit/75447c111a11bbcd57894bf7b1a8772efab20448).
The merge retained the tested tree exactly (tree `8b53972`), and the

(`unused_binding_warnings/2`, `diagnostic_id/0` — the deterministic
let-tree walk with the `_`-prefix exemption), check-pipeline wiring

## Version and boundary decision

C031 consumes `0.1.27` for the elevated binding account and `BS001`;
it adds no JSON AST version, kernel S-expression version, interface
version, artifact version, signature domain, typing rule, runtime
behavior, BEAM representation, or manifest field (the deny list
already exists), and amends no retained revision. Every predecessor
API retains its exact selection. The next unused semantic patch is
`0.1.28`.
