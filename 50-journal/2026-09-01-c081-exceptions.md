# C081 Exception Boundary

## Observations

Checklist item G081 is complete as C081, normative source-only
language revision `0.1.47` (88/141 total), Section 9's sixth
closure (6/8). The completed boundary: the three-way mechanism
partition — typed failure is a value (G103's contents);
exception-style catching is **the effect pattern** (a handler
declining to resume aborts to its result, visible in the effect
row, a library idiom over unchanged C005 — the blessing stated
descriptively, adding no rule); and `trap(reason)` is the one
terminal mechanism, never catchable (C036 unchanged). Panics are
traps with the reserved assertion/panic kind, entering with their
producers. Routing: process exits to G084 (C010's
spared-spawner stands), foreign failures map to `trap` at the
visible boundary (G095/G096 with C067's rule), cancellation to
G088, library faults to G105, outcome types to G103; C044's
reopening door is the only amendment route for a language
exception form. Zero new diagnostic families, no new public API,
no checker rule changes.

Two implementation notes. First, the **effect-pattern witness**:
a kernel `Fallback` handler whose `ask` operation clause binds
the resumption and never uses it — `(resume next) 0` — so
`main`'s request `ask 99` aborts to `0` on both stepper and BEAM:
decline-to-resume proven as one-shot escape. En route, the C132
`EFX004` lesson recurred (a `passthrough` variant handling a pure
literal rejected — the handled effect must appear in the body's
row — and was dropped). Second, the **kernel handler-operation
grammar is exactly five elements** (`operation NAME params resume
body`), so a declining clause is simply a body that never uses
the binder — no special form, exactly as the blessing's
descriptive stance claims.

The sibling compiler implementation is commit
[`e0f2a9e`](https://github.com/pcharbon70/catena/commit/e0f2a9e)
on branch `agent/c081-exceptions`, publication pending: the
compiler PR merges into `rewrite` first, then this research
promotion merges, following the established publication order.
