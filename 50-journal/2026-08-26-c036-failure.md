# C036 Runtime Failure Taxonomy

## Observations

Checklist item G036 is complete as C036 and normative source-only
language revision `0.1.32`, the third Section 4 partial to close. The
completed boundary fixes: `trap(reason)` is the single runtime failure
outcome with kinded reasons (the three-way partition — values, traps,
running — stated once at the language level); trap observability
stays kernel-verbatim (mailbox discarded, no exit signal, no spawner
effect, unobservable through handles, uninterceptable); the six
categories map — explicit panic is the kernel `trap` expression,
typed failure is an ordinary value, VM termination is operational,
and arithmetic faults, assertions, and foreign exceptions are
reserved kinds; and the per-producer entry rule forbids any second
outcome class. Zero new diagnostic families and no new public API.

Four implementation decisions worth recording. First, the **witness
targets are the stepper and BEAM, not the evaluator**: the retained
JSON AST carries no trap expression, so no `check_json` program can
trap — traps are witnessed on the kernel S-expression path, where
`Catena.check_kernel` + `Catena.compile_kernel` produce both the
definitional machine's `{:trap, reason, outcome}` and the compiled
`erlang:error({:catena_trap, reason})`, whose `ErlangError.original`
carries the reason value; the candidate chapter's boundary bullet was
refined accordingly (the reference evaluator cannot run kernel cores
and was never a constructible trap target). Second, the **process-
context witness composes two shipped shapes**: a spawner sends `42`
to a `Boom` child whose receive clause traps on the message — the
outcome record then shows the spawner `$root` terminated with its
own value 7, the child `:trapped` with `trap: 42`, and the child's
mailbox empty — the kernel's three side-effect rules visible in one
configuration. The outcome's `processes` field is a list (not a map),
and the spawner's signature shape is `(signature Int (uses Process))`
(the fixture's `launch` pattern). Third, the **classifier partition
witness** rides C029/C035: trap 3-tuples are non-values (`classify →
:trap`) while `{:catena_constructor, :Some, _}` values — the
Option-shaped answer — classify and compare as values, which is
FT-OBL-007's typed-failure-is-not-failure evidence. Fourth, the
**divergence regression** reruns C034's `spin` under a small budget:
`budget_exhausted`, never a trap — the partition's third member held
from the other side.

## Version and boundary decision

C036 consumes `0.1.32` for the single-outcome stance, the mapping,
the entry rule, and the observability elevation; it adds no JSON AST
version, kernel S-expression version, interface version, artifact
version, signature domain, typing rule, runtime behavior, BEAM
representation, manifest field, public API name, or diagnostic
family, and amends no retained revision. Every predecessor API
retains its exact selection. The next unused semantic patch is
`0.1.33`.
