# C067 Dynamic and Unsafe Boundaries

## Observations

Checklist item G067 is complete as C067, normative source-only
language revision `0.1.43` (84/141 total), Section 7's fourth
closure (9/10). The completed boundary: **unsafety cannot be
written in Catena source** — no casts, no runtime type
inspection, no unchecked operations, no compiler intrinsics, and
no reflection exist in edition `0.1`. Each exclusion carries four
arrival conditions (representation amending C006/C113 erasure,
failure classification amending C036's taxonomy, visibility, and
evidence interaction). The "how unsafety is made visible"
requirement routes to the foreign owners: any dynamic or unsafe
value entering Catena must pass a visible, typed,
failure-classified boundary owned by its arriving slice (G095
Erlang terms, G096 foreign calls, G098 NIFs), with C036's
foreign-raise mapping and the term format's refusal of
non-finite floats as the standing precedents. Zero new diagnostic
families, no new public API, no checker rule changes.

Two implementation notes. First, the **erasure witness reads the
compiled BEAM's chunk inventory directly**: a compiled fixture's
chunks are exactly the standard OTP set plus the fixed C010
metadata chunk — no specification, governance, or evidence
chunks — the artifact-level complement of C006's byte-identity
evidence (which remains the corpus's full-strength erasure
witness). Two API facts surfaced en route and are worth keeping:
`:beam_lib.info/1` on a binary returns the keyword list directly
(not `{:ok, info}`), and chunk names are charlists, not atoms.
Second, the **lifecycle `changes()` entries carry a generic
migration string** — the detailed per-feature migration note
lives in the private `migration/2` used by the informational
endpoints — so the amendment-route witness pins the change's
existence, classification, and summary rather than the note text.

The sibling compiler implementation is commit
[`ed14901`](https://github.com/pcharbon70/catena/commit/ed14901),
merged into the `rewrite` integration line by compiler PR
[#123](https://github.com/pcharbon70/catena/pull/123) at merge
commit
[`9fa4980`](https://github.com/pcharbon70/catena/commit/9fa49801a9567a803f0ca6c0a9e96ff879a6c90b).
The merge retained the tested tree exactly (tree `3587f37`), and
the compiler PR was merged before this research promotion,
following the established publication order.
