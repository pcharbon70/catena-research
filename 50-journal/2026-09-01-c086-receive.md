# C086 Selective Receive

## Observations

Checklist item P086 is complete as C086, normative source-only
language revision `0.1.46` (87/141 total), Section 9's fifth
closure (5/8). The completed boundary: the receive rule set —
FIFO scan from the oldest message, rejected messages preserved in
position, one-time removal before the body, one closed message
type, an effect-free receive form, portable conditions only
(`CND006` unchanged) — with the honest starvation statement (a
stable rejected prefix starves the receive; each attempt's scan
cost is proportional to its rejected prefix; no fairness guarantee
beyond scan order), and four routed interfaces: public syntax to
P109 (the timeout clause named as C044's explicit total fallback),
timeouts and cancellation to G088 (evaluation order, races,
totality, cancellation disposal stated as G088's obligations),
typed protocols to G087, send-side semantics to G085. Zero new
diagnostic families, no new public API, no checker rule changes.

Three implementation notes. First, the **preservation witness
design came from a corpus reading**: the C010 `launch` test
already proves selection (send trace shows both messages, receive
trace shows `Some 1` only) but its terminated processes clear
their mailboxes, so retention is observed through a **blocked
receiver** instead — a `Holder` process whose guard rejects both
messages runs to `{:quiescent, outcome}` with status `waiting` and
mailbox `[Some 0, Some 1]` in order: preservation, scan order, and
starvation demonstrated in one fixture. Second, `CND006` fires in
the backend harness (`lower_receive!`), not the kernel checker —
kernel or-pattern receives with trivial alternatives are accepted
(they need no condition sharing), exactly as C003's wording
implies — so the witness drives the harness API directly with a
JSON-path core (the harness reads `:parameters` from definitions,
which kernel cores lack). Third, the **area code collided twice**:
`SR` is structural-records' (C041), and the first RC rename sweep
accidentally renamed C041's registry rows too, requiring a careful
restore; the decision register records `RC` as the adjusted code.

The sibling compiler implementation is commit
[`b202887`](https://github.com/pcharbon70/catena/commit/b202887),
merged into the `rewrite` integration line by compiler PR
[#126](https://github.com/pcharbon70/catena/pull/126) at merge
commit
[`36387f2`](https://github.com/pcharbon70/catena/commit/36387f2b8752918c48d36df77ab2788661cfc4c2).
The merge retained the tested tree exactly (tree `75b23ec`), and
the compiler PR was merged before this research promotion,
following the established publication order.
