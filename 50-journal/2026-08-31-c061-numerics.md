# C061 Numeric Relationships

## Observations

Checklist item G061 is complete as C061, normative source-only
language revision `0.1.40` (81/141 total), Section 7's first
closure (6/10). The completed boundary: closed-set instantiation —
numeric operators are built-in primitive forms whose operands unify
with each other and instantiate over exactly `{Int, Float}`, never
resolved by trait dispatch, instance evidence, or user
overloadability, with the closed set amendable only by a new
revision. No defaulting, no implicit coercion, no literal
constraints (C018's `NM-OBL-005`/`006` re-affirmed); division,
remainder, checked and decimal arithmetic, and explicit
conversions route to G105. Zero new diagnostic families and no new
public API.

Two findings worth recording. First, the **planned witness was
impossible and the candidate documents were corrected before
promotion**: the chosen "witness via annotated float parameters"
assumed a float type spelling exists, but neither frozen frontend
has one — the JSON AST rejects a float type tag (`T012`) and the
kernel's type grammar has no `Float` (`type!` parses it as an
undeclared nominal). The slice therefore landed as the strict
correct-but-dormant pattern: the inference rule changed for real
(same-type instantiation replacing the Int-only pin), witnessed by
driving `Catena.Type.Infer` directly with `Scheme.mono(:float)`
operands — float `add` infers `Float`, Int `add` infers `Int`
unchanged, mixed rejects — with the evaluator's arithmetic running
Elixir floats natively whenever operands first reach it. Second, a
**latent order-dependent test interaction surfaced**: the c014
escript-building test purges and reloads project modules mid-suite,
which made the C047 registration test's
`function_exported?(Comprehension, :elaborate, 1)` fail under some
seeds; guarded with `Code.ensure_loaded/1` and verified across
seeds 0, 1, and the default.

The sibling compiler implementation is commit
[`fd75cb7`](https://github.com/pcharbon70/catena/commit/fd75cb7),
merged into the `rewrite` integration line by compiler PR
[#120](https://github.com/pcharbon70/catena/pull/120) at merge
commit
[`a8c3f2f`](https://github.com/pcharbon70/catena/commit/a8c3f2fc5d62f141a58926f1c7fe77769a3602a4).
The merge retained the tested tree exactly (tree `73c6d41`), and
the compiler PR was merged before this research promotion,
following the established publication order.

## Evidence

`numeric_relationships`, static-meaning lifecycle change with
migration note — the feature registration was verified present
before proceeding) and adds the
`guides/language/numeric-relationships.md` guide; the evidence is
`c061_numeric_relationships_test.exs`.


The focused corpus covers exact selection with pinned predecessor
defaults and absent dispatch entry points; the inference-engine
witnesses (float `add`/`subtract`/`multiply` inferring `Float`,
Int inferring `Int` unchanged, mixed rejecting, ordering same-type
over both members, determinism across repeated inference); the Int
arithmetic regression pin agreeing on stepper and compiled BEAM
(`10`) with the trace captured; and the exclusions (no divide,
remainder, decimal, or bignum spellings or entry points; the closed
set exactly `Int` and `Float`).
