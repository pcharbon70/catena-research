# C062 Aliases and Newtypes

## Observations

Checklist item G062 is complete as C062, normative source-only
language revision `0.1.41` (82/141 total), Section 7's second
closure (7/10). The completed boundary is one exclusion and two
routings: transparent type aliases are excluded from edition `0.1`
with four recorded arrival conditions (identity-sharing,
comparability interaction, compatibility treatment, error-message
naming); an opaque type is C022's `abstract` export routed, not
redefined; and the newtype is the nominal single-constructor
single-field datatype with its own identity, no implicit coercion
(constructor wraps, pattern unwraps, confusion rejects),
explicit-target deriving only with no instance flow through the
wrapper, nominal-spelled diagnostics, and no cost or layout
promises — representation invisibility makes "zero-cost"
unstateable, the C042 precedent applied to representation. Zero
new diagnostic families, no new public API, and no checker rule
changes: only registration, witnesses, and documentation.

Two implementation notes. First, the **witness corpus is entirely
existing machinery**: a kernel `Email` newtype constructs, matches,
and runs on stepper and BEAM (`8`); a JSON program compares
constructed wrappers with reference/BEAM trace agreement; the C023
smart-constructor idiom runs unchanged over an `abstract` export;
an explicit kernel trait instance on the wrapper typechecks and
runs (`43`) while the same program without the instance rejects —
the deriving rule's two sides; and the transparency-mode closure
(`EXP001`, including `"alias"` as an invalid mode) plus a
`(type_alias ...)` kernel parse rejection carry the exclusion.
Second, the **JSON constructor-reference qualification recurred**:
single-type groups reference constructors as
`Type.Constructor` (`Email.Email`), the C023/C035 convention — a
first draft using the bare constructor name rejected as `A004`
before the fix.

The sibling compiler implementation is commit
[`1de0a7d`](https://github.com/pcharbon70/catena/commit/1de0a7d),
merged into the `rewrite` integration line by compiler PR
[#121](https://github.com/pcharbon70/catena/pull/121) at merge
commit
[`dc54a34`](https://github.com/pcharbon70/catena/commit/dc54a34c17e67d7a71c10a70cb7c83ee91190aa9).
The merge retained the tested tree exactly (tree `f4194cf`), and
the compiler PR was merged before this research promotion,
following the established publication order.
