# Excluded Advanced Type Features

## Purpose

This map routes the D140 question — how the excluded advanced type
features stay excluded — through the archive's decision trail. The
normative answer is revision `0.1.44` in the [Excluded Advanced
Type Features Specification](../60-specification/excluded-advanced-type-features/README.md).

## The route

1. **The standing partition.** [Advanced Type
   Checking](../60-specification/type-system/advanced-type-checking.md)
   fixes both sides at `0.1.1`: the seven excluded forms with the
   profile-boundary rejection rule, and the checked profile
   (C068's predicative explicit higher rank, signature-directed
   GADTs, branch-local equalities, explicit rigid existentials).
2. **The discipline in prose.** [Remaining research
   areas](../00-inbox/remaining-catena-research-areas.md) fixes
   the seven-point arrival discipline — problem statement,
   repeated-use evidence, interaction audit, formal semantics,
   operational contract, diagnostic story, comparison with a
   library or core mechanism — and the warning against an omnibus
   advanced-features project.
3. **The precedent.** The [Pattern Contexts map](pattern-contexts.md)
   shows the shape: D046 closed when C044 recorded its exclusion
   with arrival conditions.
4. **The contract.** The [Excluded Advanced Type Features
   Specification](../60-specification/excluded-advanced-type-features/README.md):
   the seven-form table, the seven-point gate as the amendment
   route, and conformance.
5. **The reasoning and decision record.** [Catena Excluded
   Advanced Types](../20-notes/catena-excluded-advanced-types.md)
   argues the gate-not-ban reading; the [resolved
   inquiry](../40-inquiries/how-do-the-excluded-advanced-type-forms-stay-excluded.md)
   preserves the forks.
